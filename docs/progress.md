- Task 8 (Webhook ingestion and the outbox): `ingestEvent` records a provider event and applies it in one transaction, so the same event ten times in parallel changes the order once and a failed apply leaves nothing behind for the retry; `enqueue` saves provider messages with the change that causes them and `deliverNext` claims one under a lease (`for update skip locked`), asking the provider first on a retry so a worker killed after sending never sends twice; confirm and cancel are also available on a caller's transaction (`confirmOrderInTx`, `cancelOrderInTx`).
- Task 9 (The rule checker): `checkRules` runs one query per commerce rule built so far (1, 3, 4, 5, 6, 8, 11, 12) as the owner role and returns what is broken; `pnpm rules:check` prints violations and exits 1; each rule is shown to fail when its data is corrupted on purpose, and the 100-run checkout stampede ends with the checker empty every time.
